# facade-qa-render-match — مراجعة الواجهات ومطابقتها للـ Render

> **الغرض:** منهج Sherif لمراجعة وإصلاح الواجهات الخارجية لنماذج KHL مقابل الـ renders النهائية (من مراجعة ALTHUNAYYAN 2026-10-28 وقواعد KMS 2026-11-24). **متى تُستخدم:** عند مراجعة أو إصلاح الواجهات الخارجية: التشطيبات، الـ copings، الـ grooves، الـ steel shades، والـ joins — بندًا بندًا مع Element IDs.

## الفكرة الأساسية
بند واحد في كل مرة: يُتحقق منه رقميًا وبصورة بجانب الـ render من نفس الزاوية، ثم انتظار موافقة Sherif قبل التالي. الجدران حقيقية: block + طبقة تشطيب رقيقة منفصلة ومجوّفة خلفها؛ وجه واحد = مستوى واحد بفرق 0 mm. الرد بالعامية المصرية. أي ملاحظة على موضع تنطبق على كل الواجهات.

## القواعد والأرقام الأساسية
**قواعد العمل**
- Read-only على النموذج إلا بموافقة Sherif؛ الإصلاحات عبر production thread بدفعات صغيرة مُزامنة وبلا تحذيرات تظهر له.
- كل ملاحظة: Element ID (في code block قابل للنسخ) | type | level | problem | proposed fix. صيغة التقرير: item / facade / status / table / image / "approve?".
- لا تقدير أبعاد من الـ render أبدًا: من الهندسة الأصلية (نسخة central-cache الأقدم، SketchUp) أو اسأل.
- قبل حذف أو إعادة رسم عنصر واجهة: تحقق ماهيته في الـ render و SketchUp.
- المصادر: CLAUDE.md المشروع + القواعد العامة؛ استخراج الـ renders من PDF التصميم بدقة كاملة (مسح JPEG markers FFD8..FFD9، > **100 KB**) إلى `qa\render_ref\` وجرد لكل واجهة؛ واجهة بلا render = لا افتراض؛ renderان متعارضان = اسأل أيهما النهائي. SketchUp = مرجع الهندسة؛ نسخة cache قبل التعديل = مصدر الاستعادة.

**مفهوم التشطيب (paint concept)**
- Block **20** (الخارجي **30** إن نصّ المشروع) + طبقة تشطيب واحدة (paint أو stone) كجدار رقيق منفصل مربوط بالبلوك، مجوّف من الداخل.
- **المساقط تُظهر شيئين فقط: core (block) وطبقة التشطيب** (KMS 2026-11-24)؛ لا backing blocks أو fills بينهما — احذفها. التثبيت يُعرّف لاحقًا في التفاصيل.
- **الكسوة بسماكتها الحقيقية فقط** (stone **7 cm**، paint **2 cm**) حتى عند البروزات والأركان المستديرة: skin رقيق يتبع المخطط ومجوّف خلفه؛ لا كتلة حجر مصمتة.
- **جدار تشطيب واحد لكل وجه لكل مادة من الأسفل للأعلى** (Edit Profile عند التدرج)؛ لا bands مكدسة عند كل دور (+4.55 / +8.45 / +10.25...). الفواصل فقط عند الأركان وتغيير المادة والـ grooves الظاهرة في الـ render.
- التشطيب يغطي كل خرسانة/بلوك مكشوف (حواف البلاطات، بطن الكوابيل، الدراوي، الأعمدة، الكمرات)؛ الاستثناء الوحيد جدار حد الجار. **أي شريط أبيض = دهان ناقص** ← مد التشطيب (عادة إلى بطن البلاطة، مثل +4.22 لا +4.55).
- أوجه التشطيب على نفس المستوى flush: لا بروز/غوص، لا paint فوق paint أو فوق stone، لا coplanar duplicates.
- الفتحات تقطع التشطيب تلقائيًا (join مع البلوك)؛ لا فتحات يدوية ولا profile holes. لا pier بلوك مدهون **5-10 cm** بين شبابيك متجاورة — تُلصق وتكون الإطارات السوداء هي الـ mullion. لا شريط دهان بين الزجاج والحجر.
- **فتحة زجاج متصلة/باب مطوي = عنصر واحد** (door/window/curtain-wall family واحدة) — لا صف شبابيك منفصلة بشرائح بلوك بينها. اقرأ رمز الـ CAD (zigzag = folding). الطبقتان في الفتحة (زجاج + louvre خشب) في نفس الـ family. الـ family تقطع كل الجدران والطبقات (stone خارجًا، paint داخلًا)؛ إن لم تقطع: احذفها وأعد وضعها.
- الألوان: sand beige (حوالي **228,212,190**)، Riyadh stone بنمط ashlar كبير (حوالي **300x600** running bond)، أبواب خارجية داكنة، إطارات سوداء، black paint حيث يظهر في الـ render.
- تسمية الأنواع: `KHL_<PRJ>_FIN Beige Paint 25`, `..._FIN Riyadh Stone 50`, `..._FIN Black Paint 25`, `..._COPING 50`, `..._GROOVE BLACK 10`, `..._LED STRIP 10`, `..._STEEL SHADE`, `..._Glass Guard 12`. ممنوع Generic أو ASB- أو Wall 1 أو DirectShapes بلا اسم.

**الـ Copings والدراوي**
- Parapet = **0.40** فوق الخرسانة (بما فيها الأسطح الصغيرة كغرفة السائق).
- Coping = عنصر واحد لكل مسار دروة متصل، seamless عند الأركان والـ T (sketch واحد أو Join Geometry)، مباشرة على الدروة، بروز متساوٍ حوالي **45 mm**. **لا يدخل في جدار/fin أعلى** — يقف عند وجه تشطيبه.
- البلوك وكل طبقات التشطيب على الدروة تنتهي عند نفس الارتفاع وغطاء coping واحد يغطيها كلها؛ لحفظ silhouette الـ SketchUp اخفض البلوك والتشطيبات بسماكة الـ coping.

**Grooves, strips, steel**
- كل groove/strip/LED في الـ render = عنصر حقيقي مستمر يلف الأركان كما في الـ render؛ يُفضل عناصر رقيقة (جدران **10 mm**) على reveals تقطع الدهان 25 mm وتكشف البلاطة. الـ recesses فراغات حقيقية لا شريط دهان.
- Steel shade/band قطعة واحدة مستمرة (straight → arc → straight)؛ louvre canopy عنصر واحد.
- في الواجهات: استثناء العناصر السوداء (groove, black paint, steel, frames) من الـ halftone بـ view filter؛ الباقي halftone.

**العلاقات والمحاذاة الدقيقة (KMS 2026-11-24)**
- المفهوم: الالتزام بحدود المعماري (plans/CAD) وتطبيق تصميم الواجهة من SketchUp عليها؛ إنهاء منطقة 100% قبل التالية.
- **لا وضع جدار من أرقام مكتوبة/مقرّبة:** خذ الموضع من الوجه الحقيقي للجار (اتجاهه ثم الإزاحة على الـ normal). التقريب يترك فجوات **0.05-4 mm**.
- حاذِ سلسلة البلوك المرجعية أولًا ثم التشطيبات. التشطيب يبدأ وينتهي تمامًا عند أوجه الجيران.
- **كل finish wall type طبقة واحدة فقط.** الكسوة الخارجية لا تعبر داخل المبنى (تُقسم فوق السطح الأدنى).
- تشطيب السطح يقف عند الوجه الداخلي للدروة ووجه الجدار؛ لا يمر تحت الدراوي.
- Joins: التشطيب geometry-joined للبلوك؛ نهاية جدار تشطيب لا wall-join مع بلوك؛ الدروة لا end-join مع الجدار تحتها (طريقة Sherif: نسخ القطعة على الوجه الدقيق، حذف الأصل، Disallow Join، Unjoin).
- **وجه واحد = مستوى واحد:** اسرد كل جدران البلوك على الوجه وقارن الأوجه الخارجية + حواف البلاطات = 0 mm. جدران مختلفة السماكة على محور واحد (35 ثم 20 cm) تُحرك ليتطابق الوجه الخارجي والفرق للداخل. **لا تتبع درجة البلوك بالتشطيب.**
- حواف البلاطات عند وجه البلوك الخارجي خلف التشطيب؛ تغيير سماكة التشطيب (7→2 cm) يستلزم إعادة فحص كل حافة.
- **باب/شباك لا يقطع البلاطة الإنشائية:** رأس الفتحة = بطن البلاطة كحد أقصى (قارن z).
- الأركان المنحنية مماسية لخطوط الجدار المرجعية، لا من إحداثيات مرسومة.
- **التشطيب الخارجي فقط يبقى:** لا تشطيب ثانٍ على البلوك خلف skin خارجي؛ تشطيب مخفي خلف تشطيب = خطأ (افحص في المسقط: لا خطي تشطيب متتاليين).
- مزالق API: rollback صامت ("Can't keep elements joined") ⇒ كل تغيير في transaction خاص مع failures preprocessor يسجل الرسالة، وتحقق بقراءة منفصلة. profile walls: غيّر top/base عبر الارتفاع و base-offset لا خط الـ sketch؛ `Wall.Create` من profile تقع عند الـ level — اضبط base offset بعدها.

## خطوات العمل (Workflow)
1. جمع المصادر: CLAUDE.md، استخراج الـ renders وجرد كل واجهة، SketchUp، نسخة الـ cache.
2. اختيار بند واحد؛ تحديد Element IDs والمشكلة والإصلاح المقترح.
3. (بموافقة) تنفيذ الإصلاح في production thread بدفعة صغيرة مُزامنة.
4. تشغيل الفحوص read-only بعد كل sync.
5. Render للموضع من 2-3 زوايا والفحص بالعين؛ صورة واجهة + 3D من زاوية الـ render جنبًا إلى جنب.
6. إرسال الجدول + الصورة + "approve?" وانتظار الموافقة قبل البند التالي؛ تعميم الملاحظة على كل الواجهات.

## نقاط الفحص / QA Checklist
- [ ] Wall pairs متقاطعة غير مربوطة = 0
- [ ] تداخل finish-finish > 1 mm على نفس المستوى = 0؛ فجوة finish-to-block > 2 mm = 0
- [ ] Face-offset بين تشطيبات coplanar متجاورة = 0 (إلا بقبول Sherif عند تغيير مادة)
- [ ] Copings تتقاطع مع جدران أعلى أو coping-coping غير مربوطة = 0
- [ ] Probe على بعد 1 cm خارج كل حافة بلاطة + ray-cast من الشارع: لا شيء سوى التشطيب؛ النظر من 1.5 m خارجًا: أول ما يُرى تشطيب
- [ ] لا شيء (paint, generic) أمام الزجاج؛ علاقات head/sill كما في الـ render
- [ ] Hidden/dashed lines مطفأة في 3D والواجهات
- [ ] أوجه شبه flush وفجوات نهايات (0 < offset < 10 mm) وأزواج متلامسة غير مربوطة = 0
- [ ] رأس كل فتحة تحت بلاطة ≤ بطن البلاطة
- [ ] لا تشطيب مزدوج خلف skin خارجي

## أخطاء ممنوعة / تحذيرات
- رفع كل رؤوس الشبابيك للبطن بينما المقصود الـ pier المدهون بين الشبابيك ("mullion").
- حذف steel shade على أنه "generic wall" (كان DirectShape) ثم ترقيعه قطعًا بدل إعادة بنائه نظيفًا.
- مراجعات نهائية للجدران فقط مع إغفال تصادمات الـ coping والـ soffits والدرجات coplanar.
- إرسال قوائم وأحكام دون مقارنة الصورة بالـ render.
- تدريج التشطيب والدروة والـ coping لاتباع درجة بلوك 7 cm بدل محاذاة الجدار (ما ترك البلاطة خارج التشطيب)؛ وطرح باب يرتفع خلف البلاطة كسؤال بدل إصلاحه.
- قول "clean" قبل إغلاق كل البنود؛ تقدير الأبعاد من الـ render.

## مخرجات متوقعة
- لكل بند: جدول (Element ID | type | level | problem | fix) + صورة واجهة/3D بجانب الـ render + طلب موافقة.
- مجلد `qa\render_ref\` بالـ renders المستخرجة وجرد لكل واجهة.
- نموذج بواجهات مطابقة للـ render وفحوص read-only بنتيجة صفر.
