# project-baseline-review — مراجعة خط الأساس للمشروع

> **الغرض:** مراجعة مستقلة لكامل المشروع تثبّت آخر قرارات شريف كخط أساس وتكتب دروس الإغلاق. **متى تُستخدم:** عندما يطلب شريف مراجعة مشروع كامل (threads، مجلدات، محادثات)، أو تثبيت قراراته، أو دروس الإغلاق، أو تسليم المشروع لحساب آخر.

## الفكرة الأساسية
دور مستقل (ليس PM ولا تخصصًا): يقرأ، يجمع، ويكتب ملفات القواعد فقط. لا يصمم، لا يلمس النموذج، لا يغيّر قرارًا. آخر قرار لشريف يفوز دائمًا. **حدود الدور (درس WEDAD 2026-11-21):** لا يضيف أنظمة — لا بوابات مراجعة، لا معايير رقمية من ملاحظاته، لا أوامر إعادة رسم، لا اقتراح رجوع، لا جدول يعيد ترتيب أسلوبه.

## القواعد والأرقام الأساسية
- ترتيب القراءة: ذاكرة/مستندات المشروع ← على الجهاز (`<project>\claude\`): `CLAUDE.md`، `<PROJECT>_RULES.md`، `THREADS_*\00_PROTOCOL.md`، `STATUS.md`، `PROJECT_STATE.md`، `HISTORY_PROJECT.md`، سجل القرارات، كل `INBOX_*.md`، `REVIT_LOCK.txt` ← محادثات المشروع. قل دائمًا ما قُرئ وما لم يُقرأ (البحث يعيد مقاطع مطابقة فقط).
- استخراج القرارات: regex `Sherif[^|]{0,12}?(\d{1,2}:\d{2})`، ترتيب زمني، الأحدث يفوز، الأقدم في جدول "superseded".
- التعارض غير المحسوم = سؤال؛ الأسئلة مرة واحدة، مرقمة، 5 كحد أقصى، كل منها يُجاب بسطر.
- كل قاعدة بسببها ونطاقها بكلماته؛ قاعدة لحالة واحدة (lining on an RC wall) لا تُكتب كقاعدة عامة.
- ملف خط الأساس `<PROJECT>_BASELINE_<date>.md` (Project docs + الجهاز)، أقسامه: 0 ما قُرئ/لم يُقرأ؛ 1 أساس المشروع الثابت؛ 2 القواعد الحاكمة (الأقوى أولًا)؛ 3 قواعد كل تخصص؛ 4 القرارات المستبدلة (old -> new)؛ 5 الهيكل؛ 5b آخر القرارات؛ 5c الحالة الآن؛ 6 أسئلة لشريف وإجاباته؛ 7 مشاكل النظام نفسه؛ 8 الخطة.
- بعد الإجابات: قسم مؤرخ "CONSOLIDATED RULES <date>" يُضاف لـ `CLAUDE.md` (لا حذف أو إعادة كتابة لنص أقدم)؛ قسم مؤرخ أعلى `00_PROTOCOL.md`؛ سطر لكل `INBOX_*` وأوسع لـ `INBOX_PM`؛ ونسخة في `PM_FROM_BASELINE_REVIEW_<date>.md` (كاتب وحيد).
- الكتابة الآمنة على الملفات المشتركة (إلزامية): `device_stage_files` مباشرة قبل الكتابة ← الحجم المُجهّز = حجم `device_list_dir` ← بناء الملف في مجلد إخراج جديد ← commit مع `expectedMtimeMs` ← إعادة السرد والتأكد أن الحجم زاد ← الاحتفاظ بالنسخة. ممنوع commit ملف أصغر من الموجود. الاستعادة = آخر نسخة سليمة + الأسطر الموجودة فقط في النسخة القديمة + ملاحظة RESTORE بالنافذة الزمنية المفقودة.
- قواعد الهيكل: الإغلاق مع PM تخصصًا واحدًا؛ مسار المجموعة: drafter -> designer -> COORDINATION -> PM -> Sherif؛ المعماري والداخلي أولًا؛ الإرجاع فقط لخطأ رسم كبير أو clash؛ شخص غير الصانع يفتح كل صفحة كصورة؛ الـ drafters يرسمون فقط. النماذج: Opus كحد أدنى؛ Fable لـ COORDINATION ومصممي السباكة وHVAC. للمشروع الجديد: يُفضّل PM واحد يطلق مساعدًا لكل مهمة.
- قواعد الرصيد (credit): Thread بعمل مفتوح ← فحص inbox كل 30 دقيقة؛ معلّق/منتهٍ ← كل 60 دقيقة؛ عند الإغلاق فقط وبأمر شريف ← كل 5 دقائق حتى يكتب PM `PROJECT CLOSED`. لا ردود «nothing new». قراءة البايتات الجديدة فقط. تصدير الشيتات مرة لكل جولة. المحادثة الطويلة: حدّث HANDOFF وابدأ محادثة جديدة. هذه المراجعة: بحث سريع لا deep research.
- الجدولة (فقط بطلب شريف): OR-Tools CP-SAT؛ interval لكل مهمة، precedence، NoOverlap لكل thread وعلى كل مهام كتابة Revit (كاتب واحد)؛ تقليل الـ makespan ثم مجموع أزمنة الانتهاء؛ المهام الحرجة = ما يطيل الـ makespan عند +5 دقائق. الجدول لا يحل محل ترتيبه (في WEDAD كسب نصف ساعة وأغلق MEP قبل المعماري خطأً). يُحفظ `<PROJECT>_OR_SCHEDULE_<date>.md` و`claude\qa\scripts\<PROJECT>_OR_sched.py`.
- الانتقال لحساب آخر: ينتقل مجلد الجهاز فقط. احفظ `00_SWITCH_ACCOUNT.md`، و`SKILLS_EXPORT_<date>\<skill>\SKILL.md` (أعد التصدير بعد أي تحديث)، و`HANDOFF_<THREAD>.md` حديث لكل thread.
- الحديث مع شريف: عامية مصرية، قصير، النتيجة أولًا ثم ما كُتب وأين ثم ما يبقى عليه. جداول للمقارنات فقط. لا تقل «حُفظ» دون تأكيد الكتابة.

## خطوات العمل (Workflow)
1. اقرأ بالترتيب المحدد واذكر ما قُرئ/لم يُقرأ (إن لم يكن الجهاز مربوطًا اطلب من شريف فتح المحادثة من تطبيق الديسكتوب وإضافة المجلد).
2. استخرج القرارات ورتبها واكتشف الناقص من `CLAUDE.md`.
3. اكتب ملف BASELINE واطرح ≤ 5 أسئلة.
4. بعد الإجابات: أضف للملفات المشتركة بالكتابة الآمنة.
5. (اختياري بطلبه) جدول OR-Tools.
6. بعد التسليم: `<PROJECT>_CLOSEOUT_<date>.md` (ما قُرئ؛ ما أنهى المشروع فعلًا بكلماته وتواريخه؛ المنهج للمشروع القادم؛ جدول «never again» يشمل أخطاء هذه المحادثة؛ القواعد النهائية لكل تخصص؛ التسليم؛ خطوات البدء) ثم اقترح تحديثات الـ skills وأعد تصديرها للجهاز.

## نقاط الفحص / QA Checklist
- [ ] ذُكر ما قُرئ وما لم يُقرأ
- [ ] كل قاعدة بسببها ونطاقها
- [ ] الأسئلة ≤ 5 ومرقمة
- [ ] لا commit لملف أصغر؛ الحجم زاد بعد الكتابة
- [ ] لم يُحذف أو يُعاد كتابة نص قديم في `CLAUDE.md`
- [ ] كل thread له HANDOFF حديث

## أخطاء ممنوعة / تحذيرات
- إضافة بوابات أو معايير رقمية أو أوامر إعادة رسم أو اقتراحات رجوع.
- تعميم قاعدة خاصة بحالة.
- تقديم جدول كبديل عن ترتيب شريف (المعماري أولًا ثم تخصص واحد حتى 100%).
- ادعاء الحفظ دون تأكيد.
